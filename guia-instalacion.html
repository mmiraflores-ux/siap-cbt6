Qué necesitas

  • Una cuenta de Google (para Firebase). Puede ser la institucional o una creada para la Subdirección.
  • Una cuenta gratuita de GitHub (para publicar la página). Se crea en github.com/signup.
  • La carpeta cbt6-sistema descomprimida (viene en el archivo .zip).
  • Unos 30 a 40 minutos. No necesitas instalar programas ni escribir código: solo copiar y pegar en dos lugares.
Modo local

Para probar y hacer el piloto

Los datos viven solo en el navegador de esa computadora. Permite entrar “como” cualquier persona para revisar qué ve cada rol. No requiere Firebase.

En js/config.js: mode: "local" (así viene).

Modo Firebase

Para operar con todo el plantel

Cada persona entra con su correo y contraseña. Los cambios se ven al instante en todos los dispositivos y funcionan sin internet por momentos (se sincronizan al volver).

En js/config.js: mode: "firebase".

El sistema usa módulos de JavaScript, por eso no abre con doble clic sobre index.html. Siempre se abre desde una dirección web (GitHub Pages) o, en tu computadora, con la extensión “Live Server” de Visual Studio Code.

Parte A

Prueba rápida en internet (10 minutos)

A

Sube la carpeta a GitHub Pages

  1. Entra a github.com → botón verde New (nuevo repositorio).
  2. Nombre: siap-cbt6, marca Public y pulsa Create repository.
  3. En la página del repositorio elige uploading an existing file.
  4. Arrastra el contenido de la carpeta cbt6-sistema (index.html, css, js, etc.), no la carpeta misma. Pulsa Commit changes.
  5. Ve a Settings → Pages. En “Branch” elige main y / (root), y pulsa Save.
  6. Espera 1–2 minutos y recarga: aparecerá tu dirección, por ejemplo https://tu-usuario.github.io/siap-cbt6/.

Listo: ya puedes abrir el sistema en modo local desde cualquier navegador o celular.

Parte B

Datos en la nube y en tiempo real con Firebase

1

Crea el proyecto en Firebase

  1. Entra a console.firebase.google.com con tu cuenta de Google.
  2. Pulsa Crear un proyecto (o “Agregar proyecto”). Nombre: siap-cbt6.
  3. Cuando pregunte por Google Analytics, desactívalo (no se necesita) y pulsa Crear proyecto.

El proyecto queda en el plan gratuito Spark; no pide tarjeta.

4

Registra la app web y conecta el sistema

  1. Arriba a la izquierda, pulsa el engrane ⚙ → Configuración del proyecto.
  2. En “Tus apps” pulsa el ícono web </>. Apodo: SIAP. No marques Firebase Hosting. Pulsa Registrar app.
  3. Firebase muestra un bloque const firebaseConfig = {…}. Copia lo que está entre las llaves.
  4. Abre js/config.js (en GitHub: abre el archivo y pulsa el lápiz ✎ para editar) y deja así:
window.APP_CONFIG = {
  mode: "firebase",
  firebaseConfig: {
    apiKey: "AIza…",
    authDomain: "siap-cbt6.firebaseapp.com",
    projectId: "siap-cbt6",
    storageBucket: "siap-cbt6.appspot.com",
    messagingSenderId: "1234567890",
    appId: "1:1234567890:web:abc123"
  },
  superAdminEmail: "tu-correo@gmail.com",
  …

La apiKey de Firebase no es una contraseña: es pública por diseño. La protección real está en las reglas del paso 5.

5

Publica las reglas de seguridad

  1. Abre el archivo firestore.rules de la carpeta y reemplaza TU_CORREO@ejemplo.com por el mismo correo de superAdminEmail, en minúsculas.
  2. En Firebase: Firestore Database → Reglas. Borra todo lo que aparece y pega el contenido completo del archivo.
  3. Pulsa Publicar.

Estas reglas hacen que cada persona vea y modifique solo lo que le corresponde: el docente sus propios registros, el equipo de apoyo los expedientes del plantel, y nadie (ni el equipo) puede ver su propia valoración antes de enviar su autorreflexión. La bitácora de auditoría no se puede borrar.

6

Autoriza el dominio de tu página

  1. Authentication → Configuración → Dominios autorizados → Agregar dominio.
  2. Escribe tu-usuario.github.io (sin https:// ni carpeta) y guarda.

Sin este paso aparece el error auth/unauthorized-domain al iniciar sesión.

7

Primer acceso del administrador

  1. Abre tu dirección de GitHub Pages. Verás la pantalla de inicio de sesión.
  2. Pestaña Crear cuenta con el correo de superAdminEmail y una contraseña (mínimo 6 caracteres).
  3. Al entrar, el sistema sube automáticamente el catálogo inicial: 36 personas, 6 grupos, 36 unidades curriculares, las 72 asignaciones, los horarios de agosto, el calendario y el instrumento de observación.
  4. Ve a Administración → Usuarios y roles, busca tu nombre, captura tu correo y marca tus funciones (por ejemplo Docente y Docente de apoyo a Subdirección). Guarda, cierra sesión y vuelve a entrar.

8

Da de alta a la Subdirectora, el equipo y los docentes

  1. En Administración → Usuarios y roles, pulsa Editar en cada persona, escribe su correo y revisa sus roles (ya vienen sugeridos desde la lista de docentes).
  2. Comparte la dirección de la página. Cada persona entra a Crear cuenta con ese mismo correo y recibe sus permisos automáticamente.
  3. Si alguien ve “Cuenta pendiente de habilitar”, revisa que su correo esté escrito igual en su ficha.

Desde aquí todo se sincroniza en tiempo real: lo que captura una persona aparece en segundos en las pantallas de las demás.

Firebase Storage (para archivos) ya pide el plan de pago en proyectos nuevos; por eso el sistema guarda los archivos dentro de Firestore o como enlace a Drive/Classroom. Los límites pueden cambiar: consulta la página de precios de Firebase si el plantel crece. Alternativa equivalente si algún día se requiere: Supabase (también gratuito, con base de datos PostgreSQL).
